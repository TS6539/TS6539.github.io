Transcript Coder

A small browser tool for coding interview transcripts one sentence at a time, then exporting the result for thematic analysis or epistemic network analysis (ENA).

Version 0.4.2 · pre-alpha · updated 21 November 2026 · phone layout pass and guidance pass · free to use · works on computers and phones

Why I made this

I built this for my own interview study on how doctoral students learn to publish. Coding transcripts in a spreadsheet was slow, and the larger qualitative packages did not give me the sentence-level table that ENA needs. So I made the tool I wanted. One sentence is on screen, you type a code, press Enter, and move on.

It is still rough. If something breaks or feels slow, I would like to hear about it.

Where your data goes

Nowhere. The tool runs in your browser. Transcripts are not uploaded, there is no account, and your work stays in this browser when you close the tab. To move work to another computer or back it up, save a project file from the menu.

What you get out

Thematic analysis workbook. Quotes listed under each theme and code, the codebook with how often each code was used, a code-by-participant table, and every coded sentence.

ENA datasheet. One row per line, with conversation and turn columns, any participant attributes you add, and a 0/1 column for each code. It opens in webENA or rENA as is. A few rows from the demo look like this.

Known issues

  • Autosaving to a file on your computer only works in Chrome and Edge. Elsewhere, use Save project file.
  • On a phone, work is kept in that phone's browser. Save a project file to move it to a computer.
  • Sentence splitting can miss unusual punctuation. Combine or split sentences by hand when it does.
  • Projects with more than about 50 transcripts have not been tested yet.
  • The guided path covers codebook thematic analysis with a second coder. Guided steps for reflexive thematic analysis and ENA come next.
  • A second-coder file opens in place of the project in that browser, so your colleague should save their own work first if they use the tool too.

    Enter or → next · 1–9 recent codes · ? shortcuts

    Codebook

    Every code you use is listed here with how many times it is applied. Open a code to write its definition. Select codes to merge them or group them under a higher-level code, which can later become a theme.

    Check speakers

    Tell the app who each label is. Participant lines get coded. Interviewer lines are shown as context only. You can change the speaker at any sentence later.

    Paste a transcript

    Start each turn with a speaker label and a colon, such as “Interviewer:” or “P3:”. P stands for participant, so P3 is the third person you interviewed. The app splits the text into sentences and asks who is who next.

    Merge codes

    Group under a higher-level code

    Export

    Choose what you are exporting for. Participant attributes from "Participants and attributes" are added to both.

    Code columns
    File type

    In ENA, a typical setup uses Transcript as the conversation, Speaker (or an attribute) as the unit, and the code columns as codes.

    Participants and attributes

    Rename a speaker, change whether their lines get coded, and add attributes such as country, field, or year. Attributes become extra columns in both exports, so you can compare groups.

    Import a codebook

    Columns are matched by their headings: Code, Higher-level code (or Theme, Category), Definition, Example. Codes with the same name are combined.
